# Where the docs live

The public docs are **docs.deedglass.com**, built from `docs-site/` (Astro + Starlight, ADR-064).
This directory, `docs/`, holds the repo's engineering notes and specs. Each file is one of:

- **Imported:** the file here is the one source, and the site renders it at build time
  (`docs-site/scripts/sync-docs.mjs`, the `IMPORTS` table): the specs (`DEED_SPEC.md`, `INTENTS.md`,
  `THREAT_MODEL.md`, `LIMITATIONS.md`, `SECURITY_REVIEW_*.md`), the references (`POLICY_LANGUAGE.md`,
  `IDS.md`, `MCP_CLIENTS.md`, `api/versions.md`, `INIT_AND_DOCTOR.md`, `CONNECTORS.md`, `POSTGRES.md`,
  `connectors/*.md`, `SDK_PYTHON.md`, `sdk/typescript.md`) and every other engineering note, under
  Reference › Engineering notes. Edit them here.
- **Moved:** the page is hand-written in `docs-site/src/content/docs/`, and the file here is a
  one-line pointer: `QUICKSTART.md`, `FAQ.md`.
- **A generator's source:** `api/errors.md` (one page per code at `/errors/<code>/`),
  `ATTACK_SUITE.md` (generated by `make attack-report`; the site reads the same results),
  `POLICY_ERRORS.md` (one page per diagnostic at `/policies/errors/<code>/`), `SCAN.md` (the score
  formula is copied onto the scan page), `GATE.md` (the lifecycle diagram).
- **Repo only:** build and process notes (`AMENDMENTS.md`, `COPY_CATALOG.md`, `DESIGN_SYSTEM.md`,
  `DEV_LOOP.md`, `NAMING.md`, `REPO_MAP.md`, `SECURITY_BACKLOG.md`, `v0/`, `adr/`).

`node docs-site/scripts/sync-docs.mjs --list` prints the whole split. A new `docs/*.md` file goes into
one of the four lists in the same change.

## Add a page

1. Write `docs-site/src/content/docs/<section>/<slug>.mdx` with `title`, `description` (at most 160
   characters) and `lastVerified`. Pages with third-party facts list their rows: `claims: [C-0NN]`.
2. Add it to `docs-site/sidebar.mjs`.
3. Concept, Guide and SDK pages end with `## What it doesn't do` and a `<Limits>` list.
4. `make docs-check`, then `make docs-snippets` if the page has runnable blocks.

## Snippet tests

Fenced blocks opt in with their info string:

- ` ```sh test `: run against the demo stack (`make demo-up DEMO_PORT=8091`) in a temp directory set
  up like a Quickstart directory. Lines starting `$ ` are commands; the lines after one are the
  expected output, matched in order (`…` is any text). End a command with `# exit 1` when it is meant
  to fail (a denial exits 1). The Quickstart (`testEnv: init`) starts empty and runs `deedglass init`
  for real on its own ports.
- ` ```sh test=skip reason="…" `: listed with its reason, not run. A skip needs a reason.
- ` ```python check ` and ` ```ts check `: type-checked with `mypy --strict` and `tsc` against the SDKs.
- ` ```yaml workflow `: linted with actionlint and zizmor (`check-workflows.mjs`).

Copy buttons copy only the commands of a `$ ` transcript.

## Generated data

`cd docs-site && npm run gen` writes `src/data/` from the Go sources (the error catalog, the CLI's
`help --json`, the settings table, the attack results, the lifecycle diagram, the score formula,
the sample deed) and copies the Console's tokens. Never edit `src/data/` by hand; `npm run
gen:check` (in CI) fails when it is stale. Every new error code needs a `## <code>` section in
`docs/api/errors.md` in the same session.

## Gates

`make docs-check` runs every offline gate: generated data fresh, the gates' own tests, spelling
(cspell, `docs-site/dictionary.txt`), banned words, pages, drafts, pricing, claims, CSS, install
links, workflows, errors (every `doc_url` and every docs URL the product prints resolves), links and
anchors, third-party and secret scans, and JS budgets. `make docs-lighthouse` runs Lighthouse on six
pages. CI runs the offline gates in the `docs` job.

## Draft pages

Five pages describe features that ship later and carry `draft: true` with their owner session:
"Install in any client", "The playground", "Scan every pull request" and "Policy packs" (S47), and
"Pro and licences" (S48). Production builds leave drafts out (`npm run dev` shows them), and no
built page links to one. To turn one on, the owner session removes `draft`, freezes the real
commands (for S47: `action.yml`'s inputs, the comment sub-action path and the pinned SHAs; for
S48: the prices from `pricing.json`), flips its blocks from `test=skip` to `test`, re-checks its
claims rows, and runs `make docs-snippets`.
