What this pack doesn't show

  • Agents or tools that never go through Deedglass. An agent that holds its own credentials to a system Deedglass doesn't front leaves no record here.
  • Changes on databases or tables Deedglass doesn't watch: observe mode off, or tables outside the connector's publication.
  • Whether the rules suit your business. The pack shows what the enforced rules do on four fixed inputs, not on every input.
  • Anything before 17 July 2026 or outside this org, and anything about models or prompts: Deedglass records actions, not reasoning.
  • An outside opinion. Deedglass wrote this pack from the org's own records; no third party reviewed it.

How to check this pack

  1. Install the Deedglass CLI, version 0.1.0-dev or later (npx -y deedglass@latest version runs it without installing). No account is needed.
  2. In the folder that holds this file, run:
    deedglass security-pack verify .
    It checks every file against its sealed record (pack.seal.json) and checks every record in records.tar.gz: seals, hashes and the unbroken chain. One changed byte in any file fails the check and names the file.
  3. To make sure the records were sealed by Acme's own server and not by someone else's, ask Acme for its public keys and pin them:
    deedglass security-pack verify . --keys keys.json
  4. Every deed_ id in the evidence above is a record in records.tar.gz; deedglass verify records.tar.gz checks them on their own.
