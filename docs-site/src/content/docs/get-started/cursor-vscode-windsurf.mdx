All three editors read an MCP config file. Point it at the Gate's HTTP endpoint, `/mcp/native`, with an agent key.

**Before you start**

- A running Deedglass server and an agent key, from the [Quickstart](/quickstart/).

## 1. Paste the config

Each block is what `deedglass mcp snippet --transport http --client <editor>` prints.

<Tabs syncKey="editor">
  <TabItem label="Cursor">
    Put it in `.cursor/mcp.json` in your project, or `~/.cursor/mcp.json` for every project.
    <Code code={cursor.trim()} lang="json" title=".cursor/mcp.json" />
  </TabItem>
  <TabItem label="VS Code">

  </TabItem>
  <TabItem label="Windsurf">

  </TabItem>
</Tabs>

Replace `dg_test_REPLACE_ME` with your key, then reload the editor's MCP servers.

## 2. Or wrap a stdio server

The same `deedglass mcp wrap` line works in every editor. Cursor's generated form:

<Code code={cursorWrap.trim()} lang="json" title=".cursor/mcp.json" />

`deedglass mcp snippet --client cursor|vscode|windsurf --connector <name> -- <command> [args…]` prints yours.

## 3. Check it

Ask the editor's agent for something your policy denies. The tool result names the rule and the deed; `deedglass actions list` shows the same action.

## What it doesn't do

<Limits>
- Editor agents also edit files and run terminal commands without MCP. The Gate governs MCP tool calls only.
- Config file locations change between editor releases. When a path here stops working, run `deedglass mcp snippet` from the newest CLI.
- A config file with a pasted key is a secret. Keep it out of git, or use VS Code's prompt.
</Limits>
